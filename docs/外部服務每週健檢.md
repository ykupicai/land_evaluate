# 外部服務每週健檢

這條產線的成果幾乎全部依賴**別人的伺服器**——農業部地籍、NGIS 環敏、NLSC 圖磚、
內政部 API、9 個縣市都發局圖台。它們改版、下架、換欄位、裝錯憑證都不會通知我們，
而且**失敗常常是靜默的**（圖上留白、分區沒顏色、權屬全變「無法判定」），
等到做案子時才發現，通常已經在趕交期。

本健檢每週自動跑一次，把「今天還能不能用」寫成報告，只在**狀態改變**時才打擾人。

## 怎麼跑

```bash
python -X utf8 scripts/api_health.py
```

不需要 QGIS，系統 Python 即可。約 30 秒跑完 27 項。

| 旗標 | 用途 |
|---|---|
| （無） | 跑全部、寫報告、必要時在桌面留紙條 |
| `--only <id,id>` | 只跑指定項目（除錯用） |
| `--json` | 只輸出 JSON，給其他程式接 |
| `--no-report` | 不寫檔 |

離開碼：**0＝沒有 FAIL；1＝有 FAIL**。

## 產出

```
outputs/_maintenance/api_health/
  2026-09-22_0900.json   每次一份，供下次比對（不進 Git）
  最新報告.md            人看的版本，永遠是最後一次的結果
```

狀態有變化時（本來好的壞了／本來壞的復原了），桌面會多一張
`⚠ 外部服務異常_YYYYMMDD.txt`。**沒有變化就什麼都不跳**——
連續壞著的項目不會每週重複提醒，否則很快就會被無視。

## 排程

已用 Windows 工作排程器登記，名稱 `大量圖資轉換工具_外部服務健檢`，
**每週一 09:00**；電腦沒開機就順延到下次開機後補跑。

⚠ **工作排程器的「上次執行結果」顯示 `0x1` 是正常的**——那代表「這次健檢有 FAIL 項目」，
不是任務本身失敗。任務真正跑不起來會是 `0x2`（找不到檔案）之類。

```powershell
schtasks /Query /TN 大量圖資轉換工具_外部服務健檢 /V /FO LIST   # 看設定與上次結果
schtasks /Run   /TN 大量圖資轉換工具_外部服務健檢               # 立刻跑一次
schtasks /Delete /TN 大量圖資轉換工具_外部服務健檢 /F           # 取消排程
```

## 它驗什麼、不驗什麼

**驗**：服務打得通、回的東西結構正確、都市計畫圖台**註冊表對應的欄位還在**。

**不驗**：資料內容正確、圖資是不是最新版、法定認定。
圖資版本仍照各該流程查核（環敏換版看 `tgos_fetch.py`，地籍版次看 `moa.newest_version()`）。

### 為什麼不是「回 200 就算好」

三種踩過的假綠燈，都寫成了測試斷言（`tests/test_api_health.py`）：

1. **NLSC 對不存在的圖層回 HTTP 200 ＋ 0 bytes 空 gif**
   → image 型一律驗位元組數與 Content-Type。
2. **政府站台的代理／錯誤頁回 200 ＋ HTML**
   → json 型要求「解得出 JSON 且頂層有指定的鍵」。
3. **服務活著但欄位改名／圖層改編號**，程式照樣壞，而且壞得最安靜
   → 都市計畫 9 縣市直接讀 `urbanplan_fetch.COUNTY` 的 `fields` 對應，
   逐一比對 `?f=json` 的欄位清單。新北市還會先照產線的方式抓 token，
   **token 的 regex 失效也會被抓到**。

## 兩個設計上的選擇（改之前先看這裡）

### 一、登錄表不抄第二份 URL

都市計畫 9 縣市的網址**不在** `config/api_health.yaml`，而是直接讀
`scripts/urbanplan_fetch.py` 的 `COUNTY`／`LANDNUM_COUNTY` 註冊表。
在健檢裡再抄一份的話，註冊表改了、健檢還在測舊網址，**看起來全綠其實沒在測**——
那比沒有健檢更危險。

### 二、漂移檢查

每次跑會掃 `scripts/` 與 `config/` 實際出現的外部主機，和登錄表比對。
程式新接了一個服務卻忘了登錄 → 報 WARN。這是為了讓健檢的覆蓋率不隨時間腐化。
新增服務時：在 `config/api_health.yaml` 的 `服務` 加一列，
或（不是執行路徑、只是註解引用的網址）加進 `不檢查主機`。

## SSL：放寬了什麼、沒放寬什麼

本機 Python 3.14 預設帶 `VERIFY_X509_STRICT`，而**很多政府憑證缺 Subject Key
Identifier 欄位**，會被直接擋下。健檢掛上 skill `env-sensitivity-check` 的
`govtls.RelaxedStrictAdapter`，**只清掉 strict 旗標**——
CA 憑證鏈驗證與主機名檢查全部保留，**不是 `verify=False`**。

所以下列情況**仍然會 FAIL**，而且應該 FAIL：憑證過期、簽發鏈不對、
**憑證主機名不符**（對方裝錯憑證或網域換了）。

⚠ 看到「憑證主機名不符」時**不要改成關閉驗證來繞過**——先確認官方是不是換了網域。

## 新增一個要監看的服務

在 `config/api_health.yaml` 的 `服務` 底下加一列即可，不必改程式：

```yaml
  - id: 某某服務              # 歷史比對的主鍵，改了會被當成新項目
    名稱: 給人看的名字
    影響: 這條掛掉時產線的哪一步會停   # 週報上最重要的一欄
    檢查: json                  # json / image / text / python
    url: https://...
    必含鍵: [currentVersion]
    逾時: 45
```

需要呼叫產線函式來驗的（例如要先拿 token），在 `api_health.PY_PROBES` 加一個函式，
然後 `檢查: python`＋`函式: <鍵名>`。
