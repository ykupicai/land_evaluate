# QGIS 收尾順序修復（2026-09-17）

## 原因與修法

Windows 事件紀錄顯示原出圖流程在 `gdal311.dll` 發生 `0xC0000005`；
唯讀最小測試只載一個 OGR 圖層、不出圖、不用 openpyxl，也可重現相同模組與錯誤位置。
先 `exitQgis()` 再釋放圖層會崩潰；相反順序正常。
所以此次確認的是物件生命週期順序，不應再把這次收尾崩潰籠統歸因於 libxml2。

`make_maps.main()` 改為薄外層，原工作流程移至 `_run_maps(start_qgis)`。
參數解析、圖資載入、渲染與清單欄位沒有改變，初始化仍延後到輸入驗證之後。
工作完成或提早 return 時先離開工作函式，再清空 project、收集循環參照，最後關閉 QGIS。
發生例外時額外清理已退場 traceback frame 的局部參照，保留原例外／行號並往外傳，
不改成成功、不使用強制 os._exit 逃避清理。
CSV → xlsx 仍用獨立子進程，不把 openpyxl 寫檔搬回 QGIS 渲染流程。

相關檔案：`scripts/qgis_session.py`、`scripts/make_maps.py`。
`run_case` 的 maps 步驟恢復僅接受狀態碼 0，避免未來同類錯誤被當作成功。
其他舊步驟的產物新鮮度備援未擴大或移除。
