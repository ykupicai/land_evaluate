# 大量圖資轉換工具 — 設計文件

日期：2026-07-07
狀態：設計已經使用者核可，待撰寫實作計畫（writing-plans）

## 1. 目的

給定含土地資訊（縣市、鄉鎮區、地段、小段、地號）的 xlsx / PDF / 掃描圖片，
批次比對全台地籍 shp，處理地籍異動（新舊地號查詢），並為每個「案場」產出
4 張 A4 橫式主題圖（使用分區、使用地編定、國土功能分區、正射影像＋半透明
臺灣通用電子地圖套疊），同時保留 QGIS 專案檔供事後手動微調。

典型情境：一份「清潔隊備勤室非都市用地對應國土功能分區彙整表」PDF（約 90
個案場、上千筆地號）→ 約 360 張出圖。

## 2. 已確認的需求決策

| 議題 | 決策 |
|---|---|
| 國土功能分區來源 | 使用者提供之各縣市功能分區 shp（`國土功能分區/`），與地籍做**空間交集**取得（地籍 shp 無此欄位） |
| 出圖單位 | 每個**案場**一組（同案場所有地號合併為一個圖面範圍），每組 4 張 |
| 成品格式 | PNG 圖檔＋保留 QGIS 專案檔（.qgz） |
| 輸入解析 | **兩段式**：先解析成標準化中繼檔 xlsx，人工核對後才比對出圖 |
| 新舊地號查詢 | **自動查詢**內政部系統，結果輸出「異動對照清單」供使用者確認 |
| 圖面規格 | A4 橫式；比例尺依案場範圍自動取整（1/500～1/5000 常用級距） |
| 第 4 張套疊圖 | NLSC 正射影像為底＋臺灣通用電子地圖半透明疊上，基地紅框標示 |
| 操作形態 | Claude Code 對話操作；核心為可重複執行的獨立腳本，AI 只負責解析輸入與指揮 |

## 3. 技術方案選擇

採 **PyQGIS 批次腳本**（QGIS 內建 Python 環境執行）：

- 批次出圖不經過 LLM 對話，速度快、token 省、可重現。
- 天然支援 .qgz 專案輸出與 WMTS 底圖。
- QGIS MCP 僅用於除錯與使用者事後手動微調。

否決方案：全程 QGIS MCP 對話驅動（360 張圖 token 消耗過大）、
GeoPandas+matplotlib（WMTS 底圖／製圖品質／.qgz 皆需自造輪子）。

## 4. 資料現況（探勘結果，實作時直接引用）

### 4.1 地籍圖資（`地籍圖資/`，20 縣市 shp＋段藉.shp）

- CRS：EPSG:3826（TWD97 / TM2 121）。各縣市欄位結構一致（37 欄）。
- 版本標記 `Ver` = 「111年2月」→ 與現況有時間差，是新舊地號查詢的原因。
- 關鍵欄位：
  - `宗地母`、`宗地子`：各 4 位數字字串（例：331-1 地號 → 宗地母 `0331`、宗地子 `0001`；無子號 → `0000`）
  - `段`、`小段`、`縣市`、`鄉鎮`：中文名稱
  - `段碼`、`小段碼`（例 `IA0130`）、`段號`（例 `IA013004380001` = 事所碼+段碼+宗地母+宗地子）
  - `使分`＝使用分區、`使類`＝使用地類別（編定）。都市土地此二欄為 None（樣本嘉義市即如此）——出圖時以「都市土地（使用分區另查）」等說明呈現
  - `登面積`：登記面積（m²）
- `段藉.shp`：全台段/小段索引（15,385 筆），欄位含 `縣市`、`鄉鎮`、`段`、`小段`、`段小段碼`、SCNO 等，用於「中文段名 → 段碼」對應與跨縣市檢核。
- 注意：縣市檔名用「台」（台北市、台南市、台中市），輸入資料多用「臺」，需正規化。

### 4.2 國土功能分區（`國土功能分區/`，19 縣市資料夾＋圖例.xml）

- **高度異質**：各縣市資料夾層級、檔名、欄位命名皆不同；基隆市拆多個 shp
  （陸域/海域/草濫溪等補充圖層）；部分檔案缺 .prj（如基隆 1090928草濫溪）。
- 因應設計：建立**縣市圖資註冊表**（`config/county_registry.yaml`），每縣市登錄：
  地籍 shp 路徑、功能分區 shp 路徑（可多檔）、功能分區欄位名、CRS 覆寫、備註。
  實作第一步是掃描各縣市功能分區 shp 欄位並填好註冊表。
- `圖例.xml`：功能分區標準配色，轉為 QGIS 分類樣式（QML）供三張主題圖之
  國土功能分區圖使用。

### 4.3 輸入樣本（`待評估資訊/20260707-清潔隊部資訊/`)

- `20260707-清潔隊部資訊v1.pdf`（8 頁）**含文字層**，可直接抽文字，不需 OCR。
- 同內容另有 8 張掃描 JPG（頁面轉圖檔），若只有圖片則走 Claude 視覺辨識。
- 地號欄格式複雜：「五股區更寮段更寮小段 331、331-1、336-10」「城林段3、3-2…」
  「343(部分)」、同案場跨多段、國土功能分區欄含按地號分組之括號說明。

### 4.4 外部服務

- 新舊地號查詢：https://www.land.moi.gov.tw/chhtml/landnoqry/51（各縣市系統入口）
- 地段代碼查詢：https://lisp.land.moi.gov.tw/MMS/MMSpage.aspx#gobox02
- NLSC WMTS（https://wmts.nlsc.gov.tw/wmts）：`PHOTO2` 通用版正射影像、`EMAP` 臺灣通用電子地圖

## 5. 架構與資料流

```
待評估資訊/<案子>/(xlsx|pdf|jpg)
 │ 階段1【解析】Claude 對話中解析（PDF抽文字層；圖片走視覺辨識；xlsx直讀）
 ▼
outputs/<案子>/01_中繼檔.xlsx  ←✋ 使用者人工核對（低信心欄位標黃）
 │ 階段2【比對】scripts/match_parcels.py（系統 Python：geopandas/pyogrio）
 ▼
outputs/<案子>/02_比對結果.xlsx ＋ 03_無法對應清單.xlsx
 │ 階段2b【異動查詢】scripts/query_landno.py（自動查內政部新舊地號系統）
 ▼
outputs/<案子>/04_新舊地號對照清單.xlsx  ←✋ 使用者核可後回填、重跑階段2
 │ 階段3【出圖】scripts/make_maps.py（PyQGIS，QGIS 內建 Python 執行）
 ▼
outputs/<案子>/圖檔/<序號>_<案場名>_<主題>.png
outputs/<案子>/<案子>.qgz
outputs/<案子>/05_出圖清單.xlsx
```

### 5.1 階段 1：解析 → 中繼檔

- 中繼檔欄位（一列一個「地號」）：
  `案場ID｜案場名稱｜縣市｜鄉鎮區｜段｜小段｜地號原文｜宗地母｜宗地子｜部分註記｜輸入使用分區｜輸入使用地目｜輸入國土功能分區｜解析信心｜備註`
- 「輸入使用分區/地目/功能分區」保留原表值，供階段 2 與圖資值**交叉檢核**。
- 解析不確定者 `解析信心=低` 並標黃；地號展開規則（「331、331-1」逐筆拆列；
  「(部分)」記入部分註記）。

### 5.2 階段 2：比對

1. 正規化：縣市名（臺/台）、段/小段名稱 → 經 `段藉.shp` 對應段碼；地號 →
   `宗地母`(4位)-`宗地子`(4位)。
2. 從縣市地籍 shp 篩出宗地（依段碼＋宗地母＋宗地子）。
3. 屬性取值：`使分`、`使類` 直接讀；國土功能分區用宗地 polygon 與縣市功能分區
   shp 做 intersection，按面積佔比列出（一宗地可能跨兩分區，佔比 <1% 者忽略，
   閾值可調）。
4. 輸出 `02_比對結果.xlsx`（含圖資值 vs 輸入值是否一致欄）；失敗者進
   `03_無法對應清單.xlsx`，分類：`查無段小段／查無地號／縣市檔缺漏／其他`。

### 5.3 階段 2b：新舊地號自動查詢

- 讀 `03_無法對應清單.xlsx`，逐筆至內政部新舊地號系統自動查詢（瀏覽器自動化；
  各縣市系統介面若不同，先支援本次案子涉及縣市，其餘遇到再擴充）。
- 輸出 `04_新舊地號對照清單.xlsx`：`舊地號→新地號(可多筆)｜查詢狀態(成功/查無/系統異常)`。
- 使用者核可後，工具將對照回填中繼檔（保留原地號於備註），重跑階段 2。
- 查無者留在清單註明「需人工處理」，不阻擋其他案場出圖。

### 5.4 階段 3：出圖（PyQGIS）

- 每案場範圍 = 該案場所有宗地 union 的 bbox 外擴 20%（可調），比例尺就近取整
  至級距（1/500、1/1000、1/2500、1/5000；超出者取實際值進位）。
- 4 張 A4 橫式版面（共用版型）：
  1. **使用分區圖**：地籍線＋周邊宗地淡色，基地按 `使分` 分類設色＋圖例
  2. **使用地編定圖**：同上按 `使類` 設色
  3. **國土功能分區圖**：功能分區 polygon 按 `圖例.xml` 配色（半透明疊地籍），基地紅框
  4. **套疊圖**：NLSC PHOTO2 正射影像為底＋EMAP 半透明（透明度預設 50%，可調）＋基地紅框
- 共同圖面元素：標題（案場名＋主題）、圖例、比例尺、指北針、地號標註、
  出圖日期與圖資版本註記（地籍 111年2月／功能分區各縣市版本）。
- 全案輸出單一 .qgz（圖層依案場分組）＋每張圖對應之 QGIS Layout，供手動微調重出。
- `05_出圖清單.xlsx`：每張圖檔對應案場、比例尺、涵蓋地號、產出時間。

## 6. 元件切分

| 元件 | 職責 | 依賴 |
|---|---|---|
| `config/county_registry.yaml` | 縣市 → 地籍/功能分區 shp 路徑、欄位、CRS 對應 | — |
| `scripts/parse_helpers.py` | 地號正規化、段名對應、臺/台正規化（純函式，可單測） | 段藉.shp |
| 階段1 解析（Claude 對話） | 任意輸入 → 01_中繼檔.xlsx | parse_helpers |
| `scripts/match_parcels.py` | 中繼檔 → 02/03 報表 | geopandas、registry |
| `scripts/query_landno.py` | 03 → 04 對照清單 | 瀏覽器自動化 |
| `scripts/make_maps.py` | 02 → 圖檔＋.qgz＋05 | PyQGIS、registry、圖例QML |
| `styles/`（QML） | 三主題配色＋版型模板 | 圖例.xml |

## 7. 錯誤處理

- 解析：低信心標黃於中繼檔；人工核對是唯一把關點，之後全自動。
- 比對：失敗分類輸出，不中斷；輸入值與圖資值不一致者在 02 標記「待確認」。
- 功能分區：缺 .prj → registry 指定 CRS；縣市無功能分區檔（如臺北市為都市
  土地為主）→ 該欄輸出「無功能分區圖資」並照常出其餘 3 張圖。
- 出圖：單一案場失敗記入 05 清單續跑其他案場。

## 8. 測試與驗收

- `parse_helpers.py` 單元測試：地號正規化（331-1→0331/0001）、段名對應、臺/台。
- 驗收案例：本次「清潔隊部資訊」全案跑通；抽 5 個案場人工核對：
  (1) 圖面地號與中繼檔一致 (2) 使分/使類/功能分區值與原表交叉檢核結果合理
  (3) 套疊圖底圖位置正確。
- 新舊地號：以 03 清單中至少 1 筆實際異動地號驗證自動查詢有效。

## 9. 非目標（YAGNI）

- 不做 GUI；不做都市計畫使用分區之線上查詢（都市土地僅註記）；
- 不做全縣市新舊地號介面的預先適配（用到哪個縣市做哪個）；
- 不做地籍 shp 的自動更新下載。
