# .qgz 重開後圖例／圖層與交付 PNG 不一致（2026-09-24 修復）

## 現象

`make_maps.py` 存的 `<案名>_maxmap.qgz`，在 QGIS 重開後各版面**與當初匯出的 PNG 不同**。
使用者在 QGIS 開 qgz 修編時看到的一直不是交付的那張圖。

實例 `outputs/20260911_西湖北安段保護區變更住宅區`（重開 qgz 重新匯出後逐像素比對）：

| 版面 | 與交付 PNG 差異 |
|---|---|
| 001_使用分區 | 10.29% |
| 001_權屬 | 84.47% |
| 001_正射套疊 | 3.13% |
| 001_國土利用調查 | 9.06% |
| 001_臨路判定 | 1.59% |

「使用分區」版面的圖例：都市計畫分區色塊整組不見，換成案件群組標題＋基地地籍＋
周邊地籍界線，且圖例框溢出圖外。「權屬」版面則是整層公私別分色不見，只剩基地紅框。

**這類缺陷沒有任何既有驗收抓得到**：出圖當下一切正常，PNG 正確、05 清單記「成功」、
程序正常退出 0。只有把 qgz 重開再匯出才看得到。

## 三個成因（都在「這個物件到底有沒有被 project.write() 寫進去」）

1. **自訂圖例樹沒被序列化**。`setAutoUpdateModel(False)` 時 QGIS 會在圖例**內部**複製
   一棵 layer tree；原本的寫法是另建一棵 `QgsLayerTree()`、填好再 `setRootGroup()` 換進去。
   畫圖時有效，但存 qgz 時序列化的是圖例內部那棵（空的），重開後圖例退回「列出整個
   專案圖層樹」。改成直接在 `leg.model().rootGroup()` 上 `removeAllChildren()` 再 `addLayer()`。
   ‧ `scripts/build_layout.py`（maxmap 版面）、`scripts/make_maps.py`（compact 版面與總區位圖）

2. **記憶體層存不進 qgz**。只為出圖例而造的代理層（都市計畫分區色塊、`--urban-image`
   的彩繪取樣色、國土利用調查類別）與行政區界的區名標註層都用 `memory` provider，
   `project.write()` 只記下 `memory?geometry=Polygon&…` 這串 uri，重開是空的。
   改為落地成實體 gpkg 再讀回（renderer／labeling 沿用）：
   ‧ `make_maps.persist_legend_layer()` → `<案>/圖例{sfx}/<案場ID>_<用途>.gpkg`
   ‧ `district_line._persist_labels()` → `<案>/行政區界/區名標註_<案場ID>.gpkg`
   ⚠ **一個代理層一個檔**，不共用同一個 gpkg 的多張表——同一實體檔內不同表格名稱會
   觸發 GDAL/OGR 共用 SQLite 連線、`crs()`／`extent()` 持續讀成空值的問題
   （成因見 `make_maps.make_table_copies` 的 docstring）。
   落地失敗一律退回原記憶體層並記警告：PNG 不受影響，只是 qgz 存不住。

3. **權屬層根本沒進 project**。`l_own` 只 `keep_alive.append()`，沒有 `addMapLayer()`；
   沒註冊的圖層不會被寫進 qgz，重開後權屬版面只剩基地紅框與地號。已補 `addMapLayer`。

## 驗證

新增 `tests/manual/qgz_legend_check.py`：重開 `<案>_maxmap.qgz`、把**每個版面**重新匯出，
逐像素比對 `圖檔_maxmap/` 的交付 PNG。這是目前唯一抓得到本類缺陷的驗收方式。

```powershell
.\scripts\qgis_python.ps1 tests\manual\qgz_legend_check.py <案名> [<案名> ...]
```

實測結果：

- **麻豆客子寮段、七股新生段副本**（`outputs/_maintenance_20260916_0/_1`）：
  修前七主題全數不同（權屬 88.3%／90.4%，其餘皆為右下圖例區），
  修後 **14 個版面全部逐像素相同**。
- **臺北市西湖北安段副本**（都市計畫個案變更＋`--urban-image`＋行政區界）：
  5 個版面（使用地編定依都市案規則自動略過）**全部逐像素相同**；
  官方彩繪圖取樣的 16 類圖例、中山區／內湖區區名標註都正確還原。
  對照組：未修的原案件 qgz 重開後 5 個版面全數不同。
- **成果 PNG 未受影響**：`tests/manual/map_regression.py --phase candidate --require-clean-exit`
  兩案七主題各自成功、退出 0、05 清單除產出時間外與基準逐格相同；
  修前／修後 **49 張 PNG 逐像素相同**（PNG 的位元組雜湊每次都不同，不可用雜湊比對，
  必須比像素）。
- `pytest tests/ -q`：438 passed。新增 `tests/test_qgz_legend_persist.py`，把上述三個
  錯法寫成原始碼層的斷言（這三件事都不會讓出圖失敗，沒有其他自動化測抓得到）。

## 既有案件

修的是產線程式，**既有案件的 qgz 不會自己變好**，要重跑 make_maps 才會寫出正確的 qgz：

```powershell
.\scripts\qgis_python.ps1 scripts\make_maps.py <案名> --trust-shp outputs\<案名>\cadastre\基地.shp --layout maxmap --skip-extract --reuse-basemap --road-margin=0
```

`--skip-extract --reuse-basemap` 即可，不必重抓地籍與圖磚；原案件的旗標（如
`--urban-shp`／`--urban-image`）照該案 STATE.md 的「續跑指令」補上。
重跑會覆寫 `圖檔_maxmap/` 的 PNG，但本次修復不改變畫面內容（已逐像素驗證）。
