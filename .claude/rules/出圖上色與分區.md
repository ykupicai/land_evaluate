# 出圖上色與分區圖資的既定作法

碰到出圖腳本或 `styles/*.qml` 才載入。**這幾條都是已定案的作法，不要重新發明。**

## 都市計畫使用分區：全國性線上逐筆 API 沒有，但多數縣市有自己的圖台（2026-08-24 更新，9 縣市可用）

★**有登錄縣市：優先用該縣市都發局圖台，不要用本機粗版 shp**（2026-08-20 打通，
`scripts/urbanplan_fetch.py`，縣市登錄表驅動）：個別縣市有自建 ArcGIS Server REST 圖台，
`/query` 逐筆回**多邊形幾何＋分區名／用地／建蔽率／容積率／計畫區／計畫案**，**現行版**、
精度足以正確切出道路截角與細長道路（本機 2019 粗版 shp 會把幾㎡截角判錯）。
用法：`python -X utf8 scripts/urbanplan_fetch.py --county <縣市> --joined <基地.shp> --out <dir>`。

**兩種接法（`urbanplan_fetch.py` 內兩張登錄表，同一支腳本自動分流）**：
- **bbox 空間查詢**（`COUNTY` 表）：ArcGIS `/query` 吃基地外擴 bbox → 逐宗地。臺南／高雄／彰化／桃園／臺北／新北／花蓮走這條（7 穩定；新竹縣 unstable）。
- **land-number 反查**（`LANDNUM_COUNTY` 表）：自訂 API 吃「鄉鎮＋段＋地號」→ 逐宗地＋幾何。宜蘭縣／新竹市走這條，正好吃 ⓪a 現成的地段地號。`--county` 命中哪張表就走哪條，輸出 shp 格式一致。

⚠ **接新縣市的探勘法（2026-08-24 歸納）**：靜態抓首頁 JS 找 `rest/services`/`MapServer` 是第一步，但**服務網址常是後端動態注入、靜態找不到**（花蓮就是）——此時用瀏覽器開圖台、`read_network_requests` 抓實際 XHR，是最快的定位法。三種代理型態：直連（彰化/桃園/新竹）、`proxy.ashx?<URL編碼>`（臺南）、`proxy.jsp?/proxy.ashx?<不編碼>`（高雄/花蓮）。政府站憑證鏈常不全→需 `insecure`。「地段地號→分區」型 API（宜蘭/臺中）與本表 bbox→query 不同型，要另開路徑。

共通：一律 `f=json`（高雄不支援 geojson）；查詢送 EPSG:3826（inSR/outSR=3826，服務端轉換）；
輸出正規化 ASCII 欄名（COUNTY/ZONE/ZONE_USE/BCR/FAR/PLAN_AREA/PLAN_NO，值仍中文）。
仁德文賢案實測臺南：本機粗版 shp 把截角判錯，圖台逐筆正確（398＝住宅區、399＝道路用地，
與人工判斷一致）。**有登錄且穩定的縣市優先接圖台，未登錄／unstable／查無才退回本機 shp。**

**出圖接掛（2026-08-20）**：`urbanplan_fetch.py` 輸出的 shp 已含 `Color1`（依 ZONE_USE
反查 `config/urban_plan_legend.yaml` 官方色），出圖就緒。make_maps 加旗標
`--urban-shp <都市計畫_縣市圖台.shp>`：載入該圖台 shp 取代本機全台 2019 shp、自動偵測
標註欄（zone→ZONE_USE→ZONE→NAME）、吃 Color1 套 `styles/都市計畫.qml` 上色。未給旗標
＝維持本機全台 shp。流程：`urbanplan_fetch.py --county <縣市> --joined <基地.shp> --margin 300
--out <案>/都市計畫_縣市圖台` → `make_maps <案> ... --urban-shp <案>/都市計畫_縣市圖台/都市計畫_縣市圖台.shp`。
（尚未做「依縣市自動判斷要不要接圖台」，仍須各案明示旗標；自動判斷為後續工作。）

## 都市計畫土地使用分區：一律走 `Color1` data-defined，不要建分類表

`都市計畫/全台都市計畫土地使用分區.shp`（201,327 筆、EPSG:3826）的 **`Color1` 欄就是
官方數值化 RGB 色**（依都市計畫圖資格式附件三圖例；全台僅 26 色、99.99% 完整）。

- 出圖直接套 `styles/都市計畫.qml`（已設成依 `Color1` data-defined 上色，004 案驗證通過）。
- **`zone` 欄有 2,502 種「各計畫個別命名」**（例：「擬定臺南市安南區『遊2(附)』遊樂區
  細部計畫…」），照 zone 建分類表是白做工且永遠補不完 —— 一律走 Color1。
- 官方圖例對照表在 `config/urban_plan_legend.yaml`（要在圖例上寫中文分區名時查它）。

## 使用分區／使用地編定 QML：由 `build_legend_styles.py` 從樣式庫產出，外框會被剝除

`styles/使用分區.qml`（`使分`）、`styles/使用地編定.qml`（`使類`）由
`scripts/build_legend_styles.py` 從使用者 QGIS 樣式庫（`symbology-style.db`）撈符號 XML 產出，
`make_maps` **只讀不覆寫**。要改分類色／符號一律改 `build_legend_styles.py` 後重跑它產 QML，
再跑 `make_maps` 出圖。

⚠ **`make_maps` 對這兩層做 `strip_outlines()`——會把 SimpleFill 自帶外框整條剝除**
（改疊統一細灰界線 `l_gray`＋最上層紅框 `l_red`），所以**符號的「邊框色」在圖上不生效**
（2026-08-19 湖口案實踩：把特目框設綠色、圖上完全不顯示，因為被剝掉了）。
→ 想讓某分類在圖面有可辨識的視覺標記，**要用「填色紋理」不是「邊框」**：紋理層
（`LinePatternFill` 斜線等）屬填色的一部分、`strip_outlines` **不動**，圖面與圖例都會顯示，
且是填色不會被鄰宗填色蓋掉、也不與 `l_red` 基地框混淆。

**特定目的事業用地＝紅底＋綠色 45° 斜線**（2026-08-19 使用者定案）：
`build_legend_styles.special_purpose_symbol()` 建兩層 fill（下 SimpleFill 紅 227,26,28＋上
`LinePatternFill` 綠 51,160,44、45°、間距 2.2mm、線寬 0.4mm），並在載入 DB 符號後覆蓋特目。
順帶解決「甲種建築用地與特定目的事業用地填色同為純紅 227,26,28、同框難分」——特目現有綠
斜線、甲建維持純紅。**中途走過的兩條岔路（neutralize_outline 把綠拿掉、make_maps 另疊 l_grn
綠框層）皆已從程式碼移除，不要重蹈。**

## 國土功能分區：面圖層與逐筆查詢是兩種東西，別混用

| | `國土功能分區/` 各縣市 shp | skill `nluz-landzone-query` |
|---|---|---|
| 性質 | **面圖層**，畫周邊底圖用 | **權威報部版逐筆**，與清冊 1:1 |
| 覆蓋 | **僅 18/22 縣市**（缺 臺北市／嘉義市／金門縣／連江縣） | 全國 |
| 版本 | 各縣市不一（資料夾層級、檔名、欄位全都不同，故有 `config/county_registry.yaml` 統一登錄） | 報部版**草案** |

**出圖時的關鍵動作：把欄位改名成 `zone`**，否則吃不到 `styles/國土功能分區.qml`
（該 qml 是 `attr="zone"` 分類、21 類中文全名，與 nluz 回傳值字面一致；官田案已驗證命中）。

各縣市的分區值寫法高度異質，`zone_utils.normalize_zone()` 負責映射成標準全名，
**簡碼也吃得下**（已驗證：`城22`→城鄉發展地區第二類之二、`農3`→農業發展地區第三類、
`國2`→國土保育地區第二類、`海11`→海洋資源地區第一類之一）。臺南市的
`zone_field` 是 `type`，值即上述簡碼。

⚠ **`normalize_zone` 回 None 的要素會被丟掉**（`if z is None: continue`），
這是刻意的（排除行政區界／未來發展／陸域等非四大分區）——但也意味著
**「功能分區抽出 0 筆」永遠不會自己報錯**。`make_maps` 已加 0 筆警告
（「主題3 將是空白圖，勿當成成功交付」），出圖後看到該警告不要略過。
另 **功能分區的載入不可綁在「周邊地籍載入成功」之下**（兩者是不同圖資，
2026-08-04 曾因 `continue` 連坐而整層空白，詳 CLAUDE.md「踩過的坑」）。

逐筆查詢的三個正常現象，不要當成錯誤去追：

1. 平台**限流 5 秒**（145 筆約 13 分鐘）。腳本有 checkpoint，中斷可續跑。
2. **都市計畫區／國家公園區回「查無」是正常的** —— 依法無須製作使用地土地清冊。
3. `使用地` 欄大量空白是正常的 —— 草案尚未指定新編定（官田案 145 筆全空）。

⚠ 因為是報部版草案，交付口徑一律寫「**以直轄市、縣（市）政府認定內容為準**」。

### 兩者不一致時：nluz 優先（2026-08-06 使用者定案）

面圖層版本各縣市不一、僅 18/22 縣市覆蓋；nluz 是即時查即時報部版。**兩者對同一筆
地號給出不同分區值時，一律以 nluz 為準**，本機面圖層退為「周邊示意／nluz 查無時
的備援」——與本專案一貫原則同型（環敏NGIS平台vs本機圖資、路名即時圖磚vs本機
shapefile別名：即時/權威來源蓋過本機舊快照，並在交付文件標註差異）。

**工具：`scripts/nluz_landzone.py`**（需 QGIS 內建 python）——比原 skill
`nluz-landzone-query` 多三件事：①**依案型決定查不查鄰地**；②**自動比對本機面圖層**、
不同時輸出覆蓋 gpkg；③跨分區宗地特別處理（見下）。

```powershell
& "<QGIS>\bin\python-qgis-ltr.bat" scripts\nluz_landzone.py --case <案名> [--limit N]
```

**要不要查鄰地＝依案型自動分流**（`--neighbors auto`，預設；2026-08-06 使用者定案）：

| 案型 | 查詢對象 | 理由 |
|---|---|---|
| **非都市土地** | 基地 ＋ **出圖範圍內**鄰地 | 鄰地分區攸關綠帶留設側等判斷 |
| **都市計畫** | **只查基地** | 都市土地的鄰地分區走本機 `都市計畫/` shp，不靠 nluz |

判斷依據＝基地 `使分` 欄有值的比例（`detect_land_kind()`），`--neighbors on/off` 手動覆寫。
鄰地範圍用 `make_maps.compute_scale_extent()` 算出的實際出圖框（＋`NEIGH_EXPAND`），
框外不查。⚠ **這個範圍收斂幅度視案子而定、不保證大**：善南段案 197→185（只少12筆，
因該案出圖框 348×331m 與鄰地發現範圍 359×343m 差不多大）；七股案 37→23。真正的省時
來自案型分流。

⚠ **跨分區宗地不覆蓋**（2026-08-06 七股案 66-14 實測抓到）：nluz 對橫跨多分區的宗地回
**複合描述字串**（「部分海洋資源地區第一類之一、部分…第三類、部分農業發展地區第二類」），
這種值不在 QML 的 21 類分類表裡，硬覆蓋會讓該宗地**上不了色**；且本機面圖層對這種宗地
反而更精確（真的把宗地切成多塊分區面）。→ 這類**不寫進覆蓋 gpkg**，出圖沿用本機面圖層
切分，CSV 的「是否不同」欄標「跨N分區（不覆蓋…）」並保留 nluz 原文。這不違反 nluz 優先
原則——該原則處理的是「兩邊給不同**單一值**時信誰」。

⚠ 平台限流 5.5 秒/筆，先用 `--limit` 小數字試跑再放全量、筆數多時背景跑。
⚠ nluz 對都市計畫區**不是必定查無**（善南段案實測回「城鄉發展地區第一類」）——舊版
skill 文件寫的「都市計畫區平台查無」指的是使用地土地清冊那組欄位，不代表沒有國土功能
分區值，所以都市計畫案這步仍值得跑。

產出 `國土功能分區_逐筆核對.csv`（逐筆列本機值/nluz值/是否不同/採用值）＋
`國土功能分區/逐筆覆蓋.gpkg`（採用值的逐宗地面）。**`make_maps.py` 出主題3時
會自動偵測這份覆蓋 gpkg 並優先套用**（`apply_nluz_override`，未跑過這支腳本的
案子完全不受影響，行為不變）。

## 權屬圖：基地＋周邊都要框線與地號（2026-08-07 使用者定案）

`make_extra_maps.py --theme 權屬` 的既定做法，之後一律照此：

| 項目 | 基地 | 周邊地籍 |
|---|---|---|
| 來源 | `--joined`（基地.shp） | 自動吃 `<案>/cadastre/鄰地.shp`（`--neighbours` 可指定） |
| 宗地框線 | 0.4 | 0.3 |
| 地號字級 | 11 | 9 |
| 填色 alpha | `--alpha`（預設 0.55） | 低一級（0.45） |
| 另加 | 粗紅框「申請範圍」 | — |

- **圖框以基地範圍為準**，與其他六主題同尺度。不因鄰地而外擴——安南案 225 筆鄰地
  若全涵蓋會撐到 1/4000，基地縮成一小塊，反而看不出各筆權屬。
- ★**圖框範圍內的地籍都要呈現出來，不可留空白（2026-08-20 使用者定案，通則、不限權屬圖）**：
  比例尺與圖框既已固定（以基地為準），**框內所有已登記地籍都應畫出**，不能因為
  `cadastre_neighbors` 預設只抓基地周邊 50m、而讓框內 50m 外的地籍留白。空白只允許
  兩種真實情況：①該處真的無登記地籍（水域／未登錄地／母號≥9000，探測確認）②框已
  超出圖資涵蓋。**做法（2026-09-04 起已自動化）**：`cadastre_neighbors.py` 改為
  **出圖框直接向農業部框查**——把出圖框（合併框＋各案場框）∪ buffer 環整個範圍送空間
  查詢，一次取回範圍內全部宗地，跑完印**逐框覆蓋率**，`100.00%` 才算填滿。15 個既有案
  回測逐框全部 100.00%（舊路徑最低只有 53.16%）。三個操作要點：
  ①**逐案場出圖必須帶 `--sitemap`**（各案場框可能伸出合併框外）；②覆蓋率不足時訊息
  會說明成因，該留白**要在交付文件寫明**；③`--buffer` 現在只是緊鄰下限，不必再手動放大
  （舊做法：關廟深坑子段 780-44 案曾需 buffer 200m 才填滿 1/1500 圖框）。
  ⚠ **多案場案件，「其他案場」的基地宗地也要畫進本案場的周邊地籍**——`鄰地.shp` 依設計
  排除申請範圍全部宗地，`make_maps` 已補上這段（標 `是否基地=""`，不套紅框樣式）；
  漏了會在圖上出現一整塊白（麻豆案 S001 圖左下 3,168 ㎡ 白塊其實是 S002 的 258/259/260）。
  ⚠ buffer 放大只影響「呈現用」的鄰地圖層，不改變分析用的緊鄰判定（綠帶留設側、
  周邊使用地分析仍以真正緊鄰宗地為準，不因圖面填滿而納入遠處地籍）。
- **分色一律吃 `persite_stats.classify_ownership`**（全產線唯一權屬判定）。
  ⚠ 不可拿 shp 的原始字串當分類 key：兩條路徑用詞不同（TCDGIS＝公／私；
  ⓪a＝國有／直轄市有／私(推論)），拿原始值會讓公私**全部落到預設灰色**。
- ⚠ **周邊層不可再疊 `setOpacity()`**：符號已帶 alpha，再乘一次變 ~0.30，
  在正射底圖上幾乎看不見。

## 同一張圖疊多個圖層：每層必須可區辨

未指定顏色的圖層若全部套同一個預設色，圖例會出現好幾格一樣的色塊，讀者看不出哪塊
屬哪一項——**這種圖等於白畫**（2026-08-04 環敏圖實錯：自然保留區與山崩地滑同色）。

- 規則層在 `make_env_map.REGISTRY` 用 `"rgb"` 指定**語意色**：保護類偏綠、災害類偏橙紅。
- 未指定者依疊圖順序取 `GENERIC_PALETTE` 色環（色相間距 ≥60°，40% 不透明度疊在正射上
  仍分得出）。
- 覆蓋率 ≥99% 的圖層，**僅當同時有 2 個以上這樣的全覆蓋圖層疊加時**才改畫外框虛線
  不填色（真的會疊糊才退避）；**單一命中項一律給透明填色**，不退外框
  （★2026-08-20 修正：湖口案「高速公路兩側禁建限建」單一命中 100% 覆蓋，若退外框，
  虛線邊界落在圖框外，畫面近乎全空、完全看不出基地與範圍的關係——這正是外框規則
  原本要防的「疊很多層看不清楚」的反面情況）。判斷式見 `make_env_map.py` 的
  `n_full = sum(1 for _, ar in hits if ar >= 0.99*geom_area)`，`outline_only`
  僅在 `n_full >= 2` 時成立。

## 右欄圖例只有 45mm 寬

`build_layout` 以 `setWrapString("／")` 換行 → **長標籤裡沒有「／」就會被直接切掉**。
寫圖層名／類別標籤時主動放「／」斷詞，例：`坡度30~40%／僅開放性設施`、
`緩衝綠帶10公尺／總編§40`。

光柵圖層的圖例會自動多一行 **`Band 1 (Gray)`**（波段名），對讀者無意義又白占一行；
`build_layout` 已逐層挑掉該節點（`QgsMapLayerLegendUtils.setLegendNodeOrder`）。

## 底圖要照「版面最終圖框」抓，不是基地 bbox

圖框寬度由 A4 比例與**整數比例尺退階**決定，通常比 bbox 寬；照 bbox 抓底圖，成品左右
會露白邊。作法：先呼叫 `overlay_placement.place_overlays(...).extent`（純幾何、無副作用）
取得最終 extent 再抓圖磚，`build_sheet_layout` 之後重算一次必得同結果。

## 圖資無 .prj 時要自己給 CRS

本機圖資有數個圖層缺 `.prj`（例：淹水潛勢，`type` 欄為深度分級字串）。
讀進來要 `set_crs(3826)`；`check_zones.py` 會以 TWD97 bounds 反驗，落在界外就是給錯了。
