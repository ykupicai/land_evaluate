# 出圖上色與分區圖資的既定作法

碰到出圖腳本或 `styles/*.qml` 才載入。**這幾條都是已定案的作法，不要重新發明。**

## 都市計畫使用分區：全國性線上逐筆 API 沒有，但多數縣市有自己的圖台（2026-08-24 更新，9 縣市可用）

★**有登錄縣市：優先用該縣市都發局圖台，不要用本機粗版 shp**（2026-08-20 打通，
`scripts/urbanplan_fetch.py`，縣市登錄表驅動）：個別縣市有自建 ArcGIS Server REST 圖台，
`/query` 逐筆回**多邊形幾何＋分區名／用地／建蔽率／容積率／計畫區／計畫案**，**現行版**、
精度足以正確切出道路截角與細長道路（本機 2019 粗版 shp 會把幾㎡截角判錯）。
用法：`python -X utf8 scripts/urbanplan_fetch.py --county <縣市> --joined <基地.shp> --out <dir>`。

**兩種接法（`urbanplan_fetch.py` 內兩張登錄表，同一支腳本自動分流）**：
- **bbox 空間查詢**（`COUNTY` 表）：ArcGIS `/query` 吃基地外擴 bbox → 逐宗地。臺南／高雄／彰化／桃園／臺北／新北／花蓮走這條（7 穩定；新竹縣 unstable）。
- **land-number 反查**（`LANDNUM_COUNTY` 表）：自訂 API 吃「鄉鎮＋段＋地號」→ 逐宗地＋幾何。宜蘭縣／新竹市走這條，正好吃 ⓪a 現成的地段地號。`--county` 命中哪張表就走哪條，輸出 shp 格式一致。

⚠ **接新縣市的探勘法（2026-08-24 歸納）**：靜態抓首頁 JS 找 `rest/services`/`MapServer` 是第一步，但**服務網址常是後端動態注入、靜態找不到**（花蓮就是）——此時用瀏覽器開圖台、`read_network_requests` 抓實際 XHR，是最快的定位法。三種代理型態：直連（彰化/桃園/新竹）、`proxy.ashx?<URL編碼>`（臺南）、`proxy.jsp?/proxy.ashx?<不編碼>`（高雄/花蓮）。政府站憑證鏈常不全→需 `insecure`。「地段地號→分區」型 API（宜蘭/臺中）與本表 bbox→query 不同型，要另開路徑。

共通：一律 `f=json`（高雄不支援 geojson）；查詢送 EPSG:3826（inSR/outSR=3826，服務端轉換）；
輸出正規化 ASCII 欄名（COUNTY/ZONE/ZONE_USE/BCR/FAR/PLAN_AREA/PLAN_NO，值仍中文）。
仁德文賢案實測臺南：本機粗版 shp 把截角判錯，圖台逐筆正確（398＝住宅區、399＝道路用地，
與人工判斷一致）。**有登錄且穩定的縣市優先接圖台，未登錄／unstable／查無才退回本機 shp。**

--out <案>/都市計畫_縣市圖台` → `make_maps <案> ... --urban-shp <案>/都市計畫_縣市圖台/都市計畫_縣市圖台.shp`。

## 都市計畫土地使用分區：一律走 `Color1` data-defined，不要建分類表

`都市計畫/全台都市計畫土地使用分區.shp`（201,327 筆、EPSG:3826）的 **`Color1` 欄就是
官方數值化 RGB 色**（依都市計畫圖資格式附件三圖例；全台僅 26 色、99.99% 完整）。

- 出圖直接套 `styles/都市計畫.qml`（已設成依 `Color1` data-defined 上色，004 案驗證通過）。
- **`zone` 欄有 2,502 種「各計畫個別命名」**（例：「擬定臺南市安南區『遊2(附)』遊樂區
  細部計畫…」），照 zone 建分類表是白做工且永遠補不完 —— 一律走 Color1。
- 官方圖例對照表在 `config/urban_plan_legend.yaml`（要在圖例上寫中文分區名時查它）。

## ⚠ 圖台官方 renderer 可能整類回 `0,0,0`（黑），官方色優先原則的失效模式

「圖台自帶的官方 renderer 配色優先於本機色表」（彰化案定案）有一個失效情形：
**臺北市圖台對住宅區與商業區全部回 `Color1 = 0,0,0`（75 筆中 45 筆）**，照單全收會讓
**標的分區整片變成黑色不可讀**——保護區變更住宅區案裡，住宅區正是最該看清楚的那層。

→ 案件層處置（2026-09-11 內湖案）：另存 `都市計畫_縣市圖台_補色.shp`，把 `0,0,0` 依
**內政部「都市計畫圖圖例」附件三統一圖例**（`config/urban_plan_legend.yaml`）補色
（住宅區 255,255,0、商業區 255,0,63），**其餘分區維持圖台官方色不動**，兩版都保留。
判準的分界是：官方色**缺**（整類同一個無意義值）vs 官方色**與本機色表不同**；
後者仍一律以官方為準，前者才補。
★**2026-09-14 起有更好的解**：改吃都發局的**官方分區彩繪圖**（見下節），補色只是
取不到彩繪圖時的退路。

## ★ 計算用向量、出圖用官方彩繪圖（2026-09-14 使用者定案）

同一個都發局圖台其實有**兩套**都市計畫分區服務，臺北市實例：

| | 服務 | 性質 | 該站怎麼用它 | 我們怎麼用 |
|---|---|---|---|---|
| 向量 | `UrbanPlan2/UrbanPlan2/MapServer/2` | 可 query、帶屬性（分區全名/簡稱/建蔽/容積），後端表 `UPIS_TP.DBO.**USECURRENT**` | 站內 JS 註解寫「**使用分區服務**」`MapQueryUrl`，查分區用這支 | **計算**（面積、占比、逐筆分區、圖例全名）＝`urbanplan_fetch.py` |
| 彩繪圖 | `Urban/UrbanPlan/MapServer` | **圖磚快取**（singleFusedMapCache），無屬性 | 圖層清單「都市計畫使用分區圖」（內部 id `TTUrban_PlanUDD**Old**`） | **出圖**＝`urbanplan_image.py`（`/export` 取 PNG → GeoTIFF） |

兩者實測同一圖框都 75 筆、基地分區結論一致（保護區），差別只有界線數化 16.8 ㎡（0.1%）。
**出圖改吃彩繪圖的理由**：它就是官網那張圖、官方配色完整（住宅區黃、保護區淡綠…），
一次解掉上節那個「住宅區整類 0,0,0」的毛病。**計算不能吃它**：點陣、沒有屬性。

用法：`make_maps.py … --urban-shp <圖台向量.shp> --urban-image`
（`--urban-image` 不帶值＝從基地 shp 縣市欄自動判斷；縣市未登錄彩繪圖服務時自動退回
向量著色，行為與先前相同）。圖面組成：官方彩繪圖（底）＋向量層**只借標註**（全透明填色）
＋基地紅框＋圖例（向量全名＋官方色）。

三個踩過的點：
- ⚠ **彩繪圖是圖磚快取，`export` 的 `dpi` 參數對它無效**（實測 dpi=96 與 300 回同一張圖）
  → 圖上自帶的分區簡稱是**螢幕尺度**的字，貼進 300dpi 成果圖小到看不清。
  **解法＝疊一層全透明填色的同一份向量、只借它的標註**（`urban_label_lyr`），字級與其他主題一致。
- ⚠ **不要改吃向量服務的 `export`**：`UrbanPlan2/UrbanPlan2/MapServer/export` 雖是動態服務
  （dpi 有效），但它用的就是那個壞掉的 renderer——實測住宅區畫成**白底黃框**，比黑色更糟。
- ⚠ `maxImageWidth/Height = 4096`，`urbanplan_image.py` 已自動夾住；超過會被伺服器截掉。

### 圖例色一律「從官方彩繪圖取樣」，不要讀向量的 Color1

`make_maps.urban_image_legend_layer()`（`--urban-image` 時自動啟用，案件層腳本亦可直接
import）逐分區在彩繪圖上取樣顏色，保證**圖例與圖面一致**；`Color1` 只在沒有彩繪圖時才用。
兩個取樣坑都實見過，改法已內建：
- **每個多邊形只取一點會取到圖上內建的分區簡稱文字像元**（深灰字）或計畫道路留白
  → 公園用地取成深灰。改成每個多邊形取內部 5×5 網格多點、由 `sample_zone_colors()`
  取眾數，文字／邊界像元自然被稀釋。
- **大面積分區的多邊形會延伸到圖框外好幾公里**（保護區、農業區），未裁切時取樣點幾乎
  都落在彩繪圖範圍外被跳過 → **該分區整格從圖例消失**（實見：圖例 16 類獨缺保護區，
  而它正是該案標的）。故一律先 `intersection(extent)` 再取樣。
→ 有了取樣機制後，**案件層的「補色 shp」不再需要**（那是 0,0,0 黑色問題的舊解法）。

### ⚠⚠ 計算用向量圖層會有破洞，基地內的缺口要補並留痕

**臺北市 `UrbanPlan2/UrbanPlan2/MapServer/2`（計算用）不保證全覆蓋**：2026-09-14 內湖案
北安段一小段 14-1 **整筆沒有多邊形**（該點逐點查詢回 0 筆），而官方彩繪圖與
`Urban/UrbanPlan/MapServer/1`（出圖那套的可查詢層）都回「保護區」。不補的話分區組成會
變成「基地 96.76% 有分區、保護區 96.58%」，等於**把一筆本來就是保護區的地寫成無分區**。

→ `urbanplan_image.fill_zoning_gaps(county, zoning_shp, site_shp, out_shp)`：只對
「基地內未被計算用圖層覆蓋」的缺口查顯示用圖層補上，補進來的列標 `_來源='顯示用圖層(補洞)'`，
簡稱以計算用圖層現有對照翻成全名。本案補 1 筆／550.9 ㎡ → 保護區 **99.77%**、覆蓋 99.95%。
`persite_stats --overlay` 改吃 `*_補洞.shp`。
⚠ **補了什麼、補多少要看得出來**（`_來源` 欄），不可靜默混入；交付文字比照
「本機 vs 平台不一致」的既定口徑處理。
⚠ **檢查動作要成為習慣**：`persite_stats` 的 `都市計畫分區_占基地pct` 明顯低於 100% 時，
先懷疑圖層破洞，不要當成「那塊真的沒有分區」。

## 都市計畫圖例一律寫全名，圖面標註才用簡稱（2026-09-11 使用者定案）

⚠ **不可寫死欄名**：各縣市圖台的 `ZONE`／`ZONE_USE` 語意相反——

出圖 log 會印 `標註欄=… 、圖例欄=…` 兩者，接新縣市時看這行確認挑對了。

## 使用分區／使用地編定 QML：由 `build_legend_styles.py` 從樣式庫產出，外框會被剝除

`styles/使用分區.qml`（`使分`）、`styles/使用地編定.qml`（`使類`）由
`scripts/build_legend_styles.py` 從使用者 QGIS 樣式庫（`symbology-style.db`）撈符號 XML 產出，
`make_maps` **只讀不覆寫**。要改分類色／符號一律改 `build_legend_styles.py` 後重跑它產 QML，
再跑 `make_maps` 出圖。

⚠ **`make_maps` 對這兩層做 `strip_outlines()`——會把 SimpleFill 自帶外框整條剝除**
（改疊統一細灰界線 `l_gray`＋最上層紅框 `l_red`），所以**符號的「邊框色」在圖上不生效**
（2026-08-19 湖口案實踩：把特目框設綠色、圖上完全不顯示，因為被剝掉了）。
→ 想讓某分類在圖面有可辨識的視覺標記，**要用「填色紋理」不是「邊框」**：紋理層
（`LinePatternFill` 斜線等）屬填色的一部分、`strip_outlines` **不動**，圖面與圖例都會顯示，
且是填色不會被鄰宗填色蓋掉、也不與 `l_red` 基地框混淆。

**特定目的事業用地＝紅底＋綠色 45° 斜線**（2026-08-19 使用者定案）：
`build_legend_styles.special_purpose_symbol()` 建兩層 fill（下 SimpleFill 紅 227,26,28＋上
`LinePatternFill` 綠 51,160,44、45°、間距 2.2mm、線寬 0.4mm），並在載入 DB 符號後覆蓋特目。
順帶解決「甲種建築用地與特定目的事業用地填色同為純紅 227,26,28、同框難分」——特目現有綠
斜線、甲建維持純紅。**中途走過的兩條岔路（neutralize_outline 把綠拿掉、make_maps 另疊 l_grn
綠框層）皆已從程式碼移除，不要重蹈。**

**出圖時的關鍵動作：把欄位改名成 `zone`**，否則吃不到 `styles/國土功能分區.qml`

2. **使用地土地清冊欄位的「查無」，不等於國土功能分區查無**。都市案也可能回傳

### 兩者不一致時：nluz 優先（2026-08-06 使用者定案）

面圖層版本各縣市不一、僅 18/22 縣市覆蓋；nluz 是即時查即時報部版。**兩者對同一筆
地號給出不同分區值時，一律以 nluz 為準**，本機面圖層退為「周邊示意／nluz 查無時
的備援」——與本專案一貫原則同型（環敏NGIS平台vs本機圖資、路名即時圖磚vs本機
shapefile別名：即時/權威來源蓋過本機舊快照，並在交付文件標註差異）。

**工具：`scripts/nluz_landzone.py`**（需 QGIS 內建 python）——比原 skill
`nluz-landzone-query` 多三件事：①**依案型決定查不查鄰地**；②**自動比對本機面圖層**、
不同時輸出覆蓋 gpkg；③跨分區宗地特別處理（見下）。

```powershell
.\scripts\qgis_python.ps1 scripts\nluz_landzone.py --case <案名> [--limit N]
```

**要不要查鄰地＝依案型自動分流**（`--neighbors auto`，預設；2026-08-06 使用者定案）：

| 案型 | 查詢對象 | 理由 |
|---|---|---|
| **非都市土地** | 基地 ＋ **出圖範圍內**鄰地 | 鄰地分區攸關綠帶留設側等判斷 |
| **都市計畫** | **只查基地** | 都市土地的鄰地分區走本機 `都市計畫/` shp，不靠 nluz |

判斷依據＝基地 `使分` 欄有值的比例（`detect_land_kind()`），`--neighbors on/off` 手動覆寫。
鄰地範圍用 `make_maps.compute_scale_extent()` 算出的實際出圖框（＋`NEIGH_EXPAND`），
框外不查。⚠ **這個範圍收斂幅度視案子而定、不保證大**：善南段案 197→185（只少12筆，
因該案出圖框 348×331m 與鄰地發現範圍 359×343m 差不多大）；七股案 37→23。真正的省時
來自案型分流。

⚠ **跨分區宗地不覆蓋**（2026-08-06 七股案 66-14 實測抓到）：nluz 對橫跨多分區的宗地回
**複合描述字串**（「部分海洋資源地區第一類之一、部分…第三類、部分農業發展地區第二類」），
這種值不在 QML 的 21 類分類表裡，硬覆蓋會讓該宗地**上不了色**；且本機面圖層對這種宗地
反而更精確（真的把宗地切成多塊分區面）。→ 這類**不寫進覆蓋 gpkg**，出圖沿用本機面圖層
切分，CSV 的「是否不同」欄標「跨N分區（不覆蓋…）」並保留 nluz 原文。這不違反 nluz 優先
原則——該原則處理的是「兩邊給不同**單一值**時信誰」。

⚠ 平台限流 5.5 秒/筆，先用 `--limit` 小數字試跑再放全量、筆數多時背景跑。
⚠ nluz 對都市計畫區**不是必定查無**（善南段案實測回「城鄉發展地區第一類」）——舊版
skill 文件寫的「都市計畫區平台查無」指的是使用地土地清冊那組欄位，不代表沒有國土功能
分區值，所以都市計畫案這步仍值得跑。

產出 `國土功能分區_逐筆核對.csv`（逐筆列本機值/nluz值/是否不同/採用值）＋
`國土功能分區/逐筆覆蓋.gpkg`（採用值的逐宗地面）。**`make_maps.py` 出主題3時
會自動偵測這份覆蓋 gpkg 並優先套用**（`apply_nluz_override`，未跑過這支腳本的
案子完全不受影響，行為不變）。

## 權屬圖：基地＋周邊都要框線與地號（2026-08-07 使用者定案）

`make_extra_maps.py --theme 權屬` 的既定做法，之後一律照此：

| 項目 | 基地 | 周邊地籍 |
|---|---|---|
| 來源 | `--joined`（基地.shp） | 自動吃 `<案>/cadastre/鄰地.shp`（`--neighbours` 可指定） |
| 宗地框線 | 0.4 | 0.3 |
| 地號字級 | 11 | 9 |
| 填色 alpha | `--alpha`（預設 0.55） | 低一級（0.45） |
| 另加 | 粗紅框「申請範圍」 | — |

- **圖框以基地範圍為準**，與其他六主題同尺度。不因鄰地而外擴——安南案 225 筆鄰地
  若全涵蓋會撐到 1/4000，基地縮成一小塊，反而看不出各筆權屬。
- ★**圖框範圍內的地籍都要呈現出來，不可留空白（2026-08-20 使用者定案，通則、不限權屬圖）**：
  比例尺與圖框既已固定（以基地為準），**框內所有已登記地籍都應畫出**，不能因為
  `cadastre_neighbors` 預設只抓基地周邊 50m、而讓框內 50m 外的地籍留白。空白只允許
  兩種真實情況：①該處真的無登記地籍（水域／未登錄地／母號≥9000，探測確認）②框已
  超出圖資涵蓋。**做法（2026-09-04 起已自動化）**：`cadastre_neighbors.py` 改為
  **出圖框直接向農業部框查**——把出圖框（合併框＋各案場框）∪ buffer 環整個範圍送空間
  查詢，一次取回範圍內全部宗地，跑完印**逐框覆蓋率**，`100.00%` 才算填滿。15 個既有案
  回測逐框全部 100.00%（舊路徑最低只有 53.16%）。三個操作要點：
  ①**逐案場出圖必須帶 `--sitemap`**（各案場框可能伸出合併框外）；②覆蓋率不足時訊息
  會說明成因，該留白**要在交付文件寫明**；③`--buffer` 現在只是緊鄰下限，不必再手動放大
  （舊做法：關廟深坑子段 780-44 案曾需 buffer 200m 才填滿 1/1500 圖框）。
  ⚠ **多案場案件，「其他案場」的基地宗地也要畫進本案場的周邊地籍**——`鄰地.shp` 依設計
  排除申請範圍全部宗地，`make_maps` 已補上這段（標 `是否基地=""`，不套紅框樣式）；
  漏了會在圖上出現一整塊白（麻豆案 S001 圖左下 3,168 ㎡ 白塊其實是 S002 的 258/259/260）。
  ⚠ buffer 放大只影響「呈現用」的鄰地圖層，不改變分析用的緊鄰判定（綠帶留設側、
  周邊使用地分析仍以真正緊鄰宗地為準，不因圖面填滿而納入遠處地籍）。
- **分色一律吃 `persite_stats.classify_ownership`**（全產線唯一權屬判定）。
  ⚠ 不可拿 shp 的原始字串當分類 key：兩條路徑用詞不同（TCDGIS＝公／私；
  ⓪a＝國有／直轄市有／私(推論)），拿原始值會讓公私**全部落到預設灰色**。
- ⚠ **周邊層不可再疊 `setOpacity()`**：符號已帶 alpha，再乘一次變 ~0.30，
  在正射底圖上幾乎看不見。

## 環敏出圖幾何：NGIS 優先，本機 `環境敏感相關/` 退為備援（2026-09-13 使用者定案）

`ngis_sensitive.py` 跑完會把**命中圖層的平台幾何**寫成 `<案>/環敏/<平台圖層名>.geojson`
（EPSG:3826）。`make_env_map` 的 `resolve_case_override` 本來就把案件層 `環敏/` 排在本機
`環境敏感相關/` 之前，所以**檔案一落地就自動優先採用**，不必改解析邏輯。
與專案一貫原則同向（本機 vs NGIS 不一致以 NGIS 為主），且一次解決兩件事：
① 本機圖資過舊（龍崎 NR23）② **本機根本沒有該圖層**（2-31 大眾捷運兩側禁建限建）。

**實益**：圖與表從此同一個來源，數字不會互相打架。內湖案改用後，`環境敏感套疊_逐類面積.csv`
的山坡地由本機的 9,713.02 ㎡ 變成 **9,688.04 ㎡**、地質敏感區由 275.07 變成 **267.60**，
與 NGIS 回報值完全一致（先前圖用本機、表用 NGIS，兩者差 0.3%）。

三個踩過的點：
- ⚠ **`query_polygon` 吃的是 Mercator(3857) 環**（參數名就叫 `rings_merc`），與
  `overlay.analyze` 吃的 TM2(3826) 環**不同**。送錯座標系會**靜默回空**，只印
  「平台未回幾何」，看起來像平台沒資料。
- ⚠ **檔名必須是完整平台圖層名**（含 `2-27`／`2-31` 前綴）——比對是 `layer_name in p.stem`，
  少了前綴會比不中而靜默忽略。
- ⚠ NGIS 回的是**完整要素、不是裁到查詢範圍**（2-27 民航禁限建 35,123,240 ㎡ vs 本機
  松山機場 shp 同一面 35,123,241 ㎡，差 1 ㎡），所以拿來出圖不會缺周邊。
- 取幾何失敗不阻斷面積成果，會印警告並退回本機圖資；`--no-geometry` 可關閉。

⚠ **本機圖資仍不可刪**：NGIS 有已知涵蓋落差（七股氣象法禁限建 0 命中但實際涉及），
交叉核對還是要靠本機與 eland。且本機有些圖層帶 NGIS 沒有的屬性——例如
`2-27 …/機場禁限建圖資/台北機場禁限建.shp`（Big5、無 .prj 須 `set_crs(3826)`）有
**限高屬性**，內湖案就是靠它查出基地屬松山機場「轉接面（高距比 1:7、起算高程 3.98 m）」。
⚠ 「無法解析為本機圖資」只代表 `LOCAL_LAYERS` 沒登錄，**不代表資料夾裡沒有**——
看到這訊息先去 `環境敏感相關/` 翻一眼。

## 同一張圖疊多個圖層：每層必須可區辨

未指定顏色的圖層若全部套同一個預設色，圖例會出現好幾格一樣的色塊，讀者看不出哪塊
屬哪一項——**這種圖等於白畫**（2026-08-04 環敏圖實錯：自然保留區與山崩地滑同色）。

- 規則層在 `make_env_map.REGISTRY` 用 `"rgb"` 指定**語意色**：保護類偏綠、災害類偏橙紅。
- 未指定者依疊圖順序取 `GENERIC_PALETTE` 色環（色相間距 ≥60°，40% 不透明度疊在正射上
  仍分得出）。
- **覆蓋率 ≥99% 的圖層改畫 45° 斜線紋理，不用實心填色**（★2026-09-13 使用者定案，
  取代原本的「只畫虛線外框」）。理由：全覆蓋層的外框**整條落在圖框外**，圖上等於
  完全看不到、只剩圖例一格；斜線則同時交代**範圍**與**存在**，又不會把底下圖層與
  正射整片染掉。這是「要用填色紋理不是邊框」那條的延伸（同特目用地的紅底綠斜線）。
  ⚠ **間距要看尺度**：`hatch_symbol()` 預設 **5.0mm**，不是宗地符號的 2.2mm——
  這層通常涵蓋整個圖框，2.2mm 會密到糊成一片粉紅，等於沒有退讓（內湖案實見）。
- 觸發條件：`env_color_assign.is_full_coverage(cover, geom_area, len(hits))`，即**本層全覆蓋
  且還有別的圖層要看**（★2026-09-13 由原本的 `n_full >= 2` 改）。
  ⚠⚠ **`cover` 必須是本層 dissolve 後的實際覆蓋**（`make_env_map.real_coverage()`），
  **不可用 NGIS 清單的面積**（★2026-09-24 阿里山案實錯）：NGIS 逐面各回一列、同名去重後
  只留最大那列，圖層被切成好幾塊時每列都 <99%，永遠判不成全覆蓋——自來水 2 塊、水庫
  集水區 2 塊、國有林 4 塊實際都 100%，卻畫成實心填色、四層疊成一片咖啡色。
  也不可把各列相加（同圖層要素重疊會重複計算，見下一條）。一個 100% 覆蓋層鋪滿色就足以把底下
  所有層染成同一片糊色，不必等到兩個全覆蓋層。**單一命中項（`len(hits)==1`）一律給
  透明填色**，維持湖口案的修正——否則虛線邊界落在框外、畫面近乎全空。
- ⚠ **逐類面積要先 dissolve 再算**：同圖層要素彼此重疊時逐 feature 相加會重複計算
  （內湖案 2-31 捷運禁限建三個重疊面，相加 8,449 ㎡／50.3%、聯集只有 6,048 ㎡／36.04%，
  高估四成）。NGIS 對同一圖層會**逐面各回一列**，也要依圖層名去重再載入。

## 右欄圖例只有 45mm 寬

`build_layout` 以 `setWrapString("／")` 換行 → **長標籤裡沒有「／」就會被直接切掉**。
寫圖層名／類別標籤時主動放「／」斷詞，例：`坡度30~40%／僅開放性設施`、
`緩衝綠帶10公尺／總編§40`。

光柵圖層的圖例會自動多一行 **`Band 1 (Gray)`**（波段名），對讀者無意義又白占一行；
`build_layout` 已逐層挑掉該節點（`QgsMapLayerLegendUtils.setLegendNodeOrder`）。

## 底圖要照「版面最終圖框」抓，不是基地 bbox

圖框寬度由 A4 比例與**整數比例尺退階**決定，通常比 bbox 寬；照 bbox 抓底圖，成品左右
會露白邊。作法：先呼叫 `overlay_placement.place_overlays(...).extent`（純幾何、無副作用）
取得最終 extent 再抓圖磚，`build_sheet_layout` 之後重算一次必得同結果。

## 圖資無 .prj 時要自己給 CRS

本機圖資有數個圖層缺 `.prj`（例：淹水潛勢，`type` 欄為深度分級字串）。
讀進來要 `set_crs(3826)`；`check_zones.py` 會以 TWD97 bounds 反驗，落在界外就是給錯了。

## 行政區界：基地跨區時每張圖都要畫（2026-09-14 使用者指示）

基地橫跨兩個行政區（內湖／中山案）時，**每張成果圖都要看得出界線在哪**，否則讀圖的人
無從判斷哪一半屬哪一區——這與「跨兩個都市計畫」是兩件事（計畫區界另見案件層腳本），
但同樣影響辦理路徑。

**兩支引擎**：
- `scripts/district_fetch.py`：抓行政區多邊形 → `<案>/行政區界/行政區界.shp`
  （臺北市＝都發局 `UrbanPlan2/UrbanPlan2/MapServer/3`，欄位 CityName/TownName/TownCode；
  未登錄縣市可自備 shp 放同一路徑，欄位需有 `區名`）。
- `scripts/district_line.py`：出圖端 `district_layers(case_dir, project, keep, extent)`，
  **檔案存在就畫、不存在回空**——各出圖腳本呼叫一次即可，不必加旗標，舊案完全不受影響。
  已接：`make_maps`（全主題）、`make_env_map`、`make_hazard_map`、`make_extra_maps`、
  `make_locality_map`，以及案件層四張圖。

**三個畫法上的決定**（都是踩過才定的）：
1. **畫界線不畫面**：行政區是全覆蓋的面，填色會把底下所有圖層蓋掉。用深紫（90,0,110）
   粗虛線，與基地紅框、都市計畫界線（洋紅）都區隔得開。
2. **區名另開點層標**：直接標在面層上，PAL 會把標註放在**整個行政區的質心**——那通常
   在圖框外，圖上等於沒標。作法：取「該區 ∩ 圖框」最大塊的內部可容點，並向內縮 3%
   避免標在圖框邊緣被裁掉。
3. **圖層順序放在基地紅框之下、其餘主題之上**：壓不住基地，也不會被底圖蓋掉。
